# AGENTS.md

Working guide for agents in `desert-ant-core`. Read this before changing anything
about a model's identity, packaging, or documentation.

## manifest.json is the registry

`manifest.json` at the repo root describes every Desert Ant Labs model, including
the ones not built here. It is the source of truth for names, taglines, SDK
coordinates, weights repos and revisions, languages, Hugging Face front matter,
and links.

If a fact about a model appears in the README table, in a model page's generated
header, or in Hub front matter, it came from this file. Change the manifest, not
the output.

`mise run check:manifest` holds it to the repo: ids, names, summaries and weights
revisions are compared field by field against `Sources/<Product>/Catalog.swift`,
SDK coordinates against `packages/`, and `sdkVersion` against `VERSION`. Adding a
`Catalog.swift` without a manifest entry fails, and so does the reverse.

## Generated files, never hand-edited

| File | Generated by | Guarded by |
| --- | --- | --- |
| README model table (between `<!-- models:start -->` markers) | `mise run docs:render` | `mise run check:docs` |
| Model page header, install lines and footer (between the `model`, `model-install` and `model-footer` markers) | `mise run docs:render` | `mise run check:docs` |
| Hugging Face model cards (the whole file) | `mise run hub:publish`, and the weights scripts at a release | published with new weights, or on merge to the public `main` |
| Hugging Face org card table | `mise run hub:publish` | published on merge to the public `main` |
| GitHub org profile table | `mise run github:profile` | published on merge to the public `main` |

Editing any of these by hand is wasted work: the next render or sync replaces
it. A model card edited on the Hub is overwritten by the next publish. The org
card's and org profile's prose around their tables is hand-written and kept.

## Model pages

`docs/models/<id>.md` is the one page about a model. It is published three
ways: on GitHub, on desertant.com/docs (the website mirrors it), and as the
model's Hugging Face card. There is no other copy to keep in step, so a change
to a model updates its page in the same pull request.

Every page follows the same order:

1. Header, generated: name, tagline, summary, and the facts table (platforms,
   languages, weights, demo, and `Beta` while the manifest says so).
2. What the model is for: a short hand-written opening.
3. Install, generated: the install lines for each live SDK, at `sdkVersion`.
4. Usage, then any model-specific sections.
5. Files, inputs and outputs, languages, results and performance, limitations,
   and what the model is built on, as each model needs.
6. License and citation, generated.

The README covers what the models have in common (platform requirements,
downloads and caching) and nothing per-model.

A model with a live SDK must have a page, and a model without one must not:
`check:manifest` fails either way round. `check:docs` also fails a page that:

- has a relative link that resolves to nothing in this repo,
- states its lifecycle in prose ("beta"), which goes stale when the manifest
  moves on: the generated header states it,
- has a "Changes in this release" or "Status" section, which belongs in the
  release notes: a page describes the current version only,
- has a hand-written License or Citation section.

## Hub cards

A model's Hugging Face card is its page, rendered by `renderHubCard`: the Hub's
front matter from the manifest, and relative links rewritten (a sibling model
page to its page on desertant.com, anything else to GitHub). Keys the manifest
doesn't hold, such as `model-index`, go in `docs/models/<id>.hub.yml`, which the
render merges in. Write nothing on the Hub: the next publish replaces it, and
`private/check-release` names any card someone changed there.

`THIRD_PARTY_NOTICES.md` is the one file beside a card that isn't generated. It
describes the weights, so it travels with each weights tag and
`private/publish-model` copies it. Every page links it.

A card always goes up beside the weights it describes, because a page and the
weights pin in the same commit describe each other:

1. **Before a release**, the page changes here like any file: the engineer who
   pins new weights updates its facts in the same pull request, and marketing
   edits its words in their own pull requests. Nothing is public yet.
2. **At a release**, `private/sync-public` (or `private/publish-model`, for weights
   published ahead of a release) renders the card from this repo's `main` and
   commits it in the same Hugging Face commit as the weights, then tags that
   commit. The tag holds the card for its own weights, and main shows it at once.
   Words are final at that step: a later change reaches main, never the tag. A
   model with no new weights in the release gets its card on main when the
   public release PR merges, through `hub-sync`.
3. **After a release**, a fix to a page is made here like any change, and goes
   out with the next release. A page changed on the public repo is published by
   `hub-sync` when it merges there, and never overwritten: `private/check-release`
   stops a release until this repo holds the same change.

`hub:publish` only writes a card when Hugging Face main holds the weights the
page pins (no file both have differs). Weights published ahead of a release
leave the card alone until the release that pins them. Each card's weights row
links to the files at the pinned tag, the ones the SDK downloads. Tags made
before this flow keep the card that was on main when they were made, which
describes the weights before theirs.

Models with no live SDK (closed beta) have no page, so their cards are left
alone. Internal models' cards are never touched.

## Before you push

    mise run test

That runs `check:manifest`, `check:links` and `check:docs` alongside the suites.
A manifest edit without `mise run docs:render` fails `check:docs`, and a dead URL
fails `check:links`.

## Adding a model

1. Add `Sources/<Product>/Catalog.swift`. Everything else discovers models from
   the filesystem, so no list needs editing.
2. Add the matching `manifest.json` entry, keeping models ordered A-Z by id.
3. Add `docs/models/<id>.md` with the `model`, `model-install` and
   `model-footer` markers, in the order under "Model pages". Required as soon as
   any SDK is `live`, forbidden before. Its Hugging Face card is this page, and
   it goes up with the model's weights at the release that publishes them.
4. Run `mise run docs:render` and commit the generated changes with it.
5. Add `packages/<model>-node` and `packages/<model>-kotlin` if the model ships
   those SDKs, and set `sdks.*.status` to match. The check compares them.

## Rules that are easy to get wrong

**Language codes.** Every `languages` block carries a `basis`. Use `derived` only
when the codes are computed from an artifact we ship (Tongue's are recomputed
from `tongue_meta.json` on every run and must match). Use `declared` for a
published list. Use `inherited` for a base model's pretraining coverage we have
never evaluated per language, and leave `codes` null there. Do not invent codes
to fill the field.

**Lifecycle.** The tables split on whether anything is installable. A model with
a live SDK is in the main table; everything else is `closed-beta` and goes in the
second table under it, which promises nothing to install. Do not mark a model
stable to move it up: ship an SDK.

**Internal models.** `visibility: internal` is separate from lifecycle and means
the Hub card is never touched. `face` is gated on the Hub.

**Versions.** One `VERSION` governs every artifact in this repo. Use
`mise run set-version X.Y.Z`, which also renders the docs. Do not set a version
whose `@desert-ant-labs/core` is not yet published to npm: `npm version` then
fails to resolve on the way back down and the tree needs hand-editing.

**Weights revisions** are per model and live in both `Catalog.swift` and the
manifest. They have nothing to do with `VERSION`.

## Hub publishing

`.github/workflows/hub-sync.yml` publishes to Hugging Face and to the GitHub org
profile (`Desert-Ant-Labs/.github`) on any merge to the public `main` touching
`docs/models/`, `manifest.json`, `Tools/manifest-docs.mjs`, `mise-tasks/hub/**`,
or the workflow itself. It needs the `HF_TOKEN` secret with write access to all repos under the
`desert-ant-labs` org, and `ORG_PROFILE_TOKEN` with contents:write on
`Desert-Ant-Labs/.github`. Without either, that half of the run previews instead
of failing.

A manual dispatch defaults to a dry run. Preview locally with
`mise run hub:publish --dry-run`, which needs no token. It writes each rendered
card to `.build/hub/<id>.md` beside the live one, `.build/hub/<id>.live.md`, so
the change reads as a diff.

## House style

- No em dashes or en dashes in anything you write: code comments, docs, commit
  messages, PR bodies. Use hyphens, commas, parentheses, or separate sentences.
- Comment what the code does not show: a constraint, a landmine, a why. Do not
  restate the mechanism.
- Keep PR bodies short, and do not hard-wrap them. GitHub renders a single
  newline as a line break, so one paragraph or bullet is one physical line.
- Keep customer context out of commit messages. This repo is public.
