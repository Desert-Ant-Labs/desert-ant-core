# AGENTS.md

Working guide for agents in `desert-ant-core`. Read this before changing anything
about a model's identity, packaging, or documentation.

## manifest.json is the registry

`manifest.json` at the repo root describes every Desert Ant Labs model, including
the ones not built here. It is the source of truth for names, taglines, SDK
coordinates, weights repos and revisions, languages, Hugging Face front matter,
and links.

If a fact about a model appears in the README table, on a Hub card, or in Hub
front matter, it came from this file. Change the manifest, not the output.

`mise run check:manifest` holds it to the repo: ids, names, summaries and weights
revisions are compared field by field against `Sources/<Product>/Catalog.swift`,
SDK coordinates against `packages/`, and `sdkVersion` against `VERSION`. Adding a
`Catalog.swift` without a manifest entry fails, and so does the reverse.

## Generated files, never hand-edited

| File | Generated by | Guarded by |
| --- | --- | --- |
| README model table (between `<!-- models:start -->` markers) | `mise run docs:render` | `mise run check:docs` |
| Model page headers (between `<!-- model:start -->` markers) | `mise run docs:render` | `mise run check:docs` |
| Hugging Face card identity (between `<!-- model:start -->` markers) | `mise run hub:publish` | published on merge to `main` |
| Hugging Face org card table | `mise run hub:publish` | published on merge to `main` |
| GitHub org profile table | `mise run github:profile` | published on merge to `main` |

Editing any of these by hand is wasted work: the README table is reverted by the
next render, and a card's identity block is rewritten by the next sync. Only the
marked blocks are ours. A Hub card's documentation and the org card's prose are
hand-written and preserved.

## Model pages

`docs/models/<id>.md` is how to USE a model through the SDK, and the only place
usage examples live. What a model IS lives on its Hub card: specs, taxonomy,
benchmarks, limits. Cards link here rather than repeating it. The README covers what the models have in
common (platform requirements, downloads and caching) and nothing per-model.

A page is two halves. The block between the `<!-- model:start -->` markers is
generated from the manifest: identity, the facts table, and the install lines
for each live SDK, which carry `sdkVersion` so a release bump rewrites all of
them. Everything below is hand-written, because which example a reader needs
first is a judgement no manifest field holds.

A model with a live SDK must have a page, and a model without one must not:
`check:manifest` fails either way round.

## Hub cards

A model card is written and versioned on the Hub, not here. That repo has commit
history, and the numbers on a card come from the training repo rather than from
this one, so this repo has no way to verify a figure it would hold.

`hub:publish` syncs one thing: the identity block between `<!-- model:start -->`
markers, from `manifest.json`. Everything below is left alone. **A card with no
markers is refused, not adopted**, so bringing one under the sync means adding
the markers on the Hub by hand, once.

It did not work this way until 2026-08-27. `renderCard` returned the identity
block and nothing else, so two syncs, on 08-21 and 08-24, replaced every public
card whole: clear went from 168 lines to 29, redact from 194 to 52, emo from 115
to 47, and redact's benchmark section went with them. `docs/hub-cards/` held an
archived copy and is gone with the same commit, because the Hub's own history is
the restore path and a second copy only drifts.

## Before you push

    mise run test

That runs `check:manifest`, `check:links` and `check:docs` alongside the suites.
A manifest edit without `mise run docs:render` fails `check:docs`, and a dead URL
fails `check:links`.

## Adding a model

1. Add `Sources/<Product>/Catalog.swift`. Everything else discovers models from
   the filesystem, so no list needs editing.
2. Add the matching `manifest.json` entry, keeping models ordered A-Z by id.
3. Add `docs/models/<id>.md` with the `<!-- model:start -->` markers and the
   usage examples. Required as soon as any SDK is `live`, forbidden before.
4. Run `mise run docs:render` and commit the generated changes with it.
5. Add `packages/<model>-node` and `packages/<model>-kotlin` if the model ships
   those SDKs, and set `sdks.*.status` to match. The check compares them.

## Rules that are easy to get wrong

**Language codes.** Every `languages` block carries a `basis`. Use `derived` only
when the codes are computed from an artifact we ship (Tongue's are recomputed
from `tongue_meta.json` on every run and must match). Use `declared` for a
published list. Use `inherited` for a base model's pretraining coverage we have
never evaluated per language, and leave `codes` null there. Do not invent codes
to fill the field.

**Lifecycle.** The tables split on whether anything is installable. A model with
a live SDK is in the main table; everything else is `closed-beta` and goes in the
second table under it, which promises nothing to install. Do not mark a model
stable to move it up: ship an SDK.

**Internal models.** `visibility: internal` is separate from lifecycle and means
the Hub card is never touched. `eye` and `face` are gated on the Hub; `who` is
public but not advertised.

**Versions.** One `VERSION` governs every artifact in this repo. Use
`mise run set-version X.Y.Z`, which also renders the docs. Do not set a version
whose `@desert-ant-labs/core` is not yet published to npm: `npm version` then
fails to resolve on the way back down and the tree needs hand-editing.

**Weights revisions** are per model and live in both `Catalog.swift` and the
manifest. They have nothing to do with `VERSION`.

## Hub publishing

`.github/workflows/hub-sync.yml` publishes to Hugging Face and to the GitHub org
profile (`Desert-Ant-Labs/.github`) on any merge to `main` touching
`manifest.json`, `Tools/manifest-docs.mjs`, `mise-tasks/hub/**`, or the workflow
itself. It needs the `HF_TOKEN` secret with write access to all repos under the
`desert-ant-labs` org, and `ORG_PROFILE_TOKEN` with contents:write on
`Desert-Ant-Labs/.github`. Without either, that half of the run previews instead
of failing.

A manual dispatch defaults to a dry run. Preview locally with
`mise run hub:publish --dry-run`, which needs no token, or render the cards to
`.build/hub/` with `mise run hub:sync`.

## House style

- No em dashes or en dashes in anything you write: code comments, docs, commit
  messages, PR bodies. Use hyphens, commas, parentheses, or separate sentences.
- Comment what the code does not show: a constraint, a landmine, a why. Do not
  restate the mechanism.
- Keep PR bodies short, and do not hard-wrap them. GitHub renders a single
  newline as a line break, so one paragraph or bullet is one physical line.
- Keep customer context out of commit messages. This repo is public.
